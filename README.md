# TriostackOne – Document API microservice

Implements the *Document API Microservice Master Report*: a typed, versioned, tenant-isolated mutation layer for
Website Builder pages. Node.js + TypeScript + Express 5 + PostgreSQL (`pg`), BIGINT ids everywhere.

## Quick start

```bash
npm install
cp .env.example .env          # then edit secrets (.env is git-ignored)
docker compose up -d          # PostgreSQL 16 using the POSTGRES_* values from .env
npm run migrate               # applies db/migrations/*.sql
npm run dev                   # http://localhost:3000
npm run test:unit             # domain logic, no DB needed
npm run test:api              # every endpoint over HTTP against the real DB (needs docker compose + migrate)
npm test                      # both
```

## Credentials

All secrets live in `.env` (git-ignored, see `.gitignore`): `DATABASE_URL`, `POSTGRES_*`, `JWT_SECRET`.
Only `.env.example` (placeholders) is meant to be committed. `docker-compose.yml` reads the same `.env`.

## Authentication

Every `/api/v1` route needs `Authorization: Bearer <JWT>` (HS256, signed with `JWT_SECRET`) with claims
`sub` (actor id), `tenantId`, `organizationId`, `workspaceId`, `scopes[]`, `roles[]` – all ids as **strings**.
Tenant/org/workspace are taken only from the verified token; client-supplied values are ignored.
Scopes: `document:read`, `document:write`, `document:restore`, `document:publish`, `document:ai`,
`document:import` (or `document:*`). In production the token comes from the identity service;
for local use run `npm run token -- --tenant 1001 --scopes document:*`.

## Postman

Files in [postman/](postman): `Document-API.postman_collection.json` and `Document-API.postman_environment.json`.

1. Import the collection(s) and **`Document-API.local.postman_environment.json`** (generated by `npm run postman:build`
   from your `.env`; it already contains `jwtSecret` and is git-ignored). Select it as the active environment.
   If `.env` is missing the file is generated with a blank `jwtSecret` for you to fill in.
2. Authentication is `Authorization: Bearer <accessToken>` on every request (collection-level Bearer auth). The
   collection pre-request script signs a short-lived HS256 JWT from `jwtSecret` for each request - claims `sub`,
   `tenantId`, `organizationId`, `workspaceId`, `scopes`, `roles`. Alternative: leave `jwtSecret` empty and paste a JWT
   from `npm run token` into `token`. A blank `token` in your environment cannot break it. Requests also send
   `Accept`/`Content-Type: application/json`, and builder actions send a fresh `Idempotency-Key` (`{{$guid}}`).
   Don't commit a filled-in environment (`postman/*.local.*` is git-ignored).
3. Run **`Document-API.postman_collection.json`** top-to-bottom (Collection Runner): 50 requests, **every one returns
   200 OK** (create, all 19 actions, validate, idempotent replay, revisions/compare/restore/reset, publish, locks,
   duplicate, scoped tokens). Error cases (409/422/403/404...) are covered by `npm test`.

CLI: `npx newman run postman/Document-API.postman_collection.json --env-var jwtSecret=<secret>`.
Regenerate the files with `npm run postman:build`.

Every successful response is `200 OK` with `{ "success": true, "data": ..., "meta": { "requestId" } }`, including create,
duplicate, lock acquire and lock release (`data: { "released": true }`). Errors use the error envelope and 4xx codes.

## Endpoints (`/api/v1`)

| Method | Path | Scope |
|---|---|---|
| POST | `/pages/:pageId/document` – create empty document | write |
| GET | `/pages/:pageId/document[?revision=n]` | read |
| POST | `/pages/:pageId/actions` – apply `BuilderAction[]` (needs `expectedRevision`, optional `Idempotency-Key`) | write |
| POST | `/pages/:pageId/document/validate` – dry run | write |
| POST | `/pages/:pageId/document/duplicate` – copy to `targetPageId` | write |
| POST | `/pages/:pageId/document/reset` | restore |
| POST | `/pages/:pageId/publish` | publish |
| GET | `/pages/:pageId/revisions`, `/revisions/compare?from=&to=`, `/revisions/:revisionId` | read |
| POST | `/pages/:pageId/revisions/:revisionId/restore` | restore |
| GET/POST/DELETE | `/pages/:pageId/locks[/:lockId]` | read / write |
| GET | `/components` – component registry | any |
| GET | `/health`, `/health/ready` (no auth, outside `/api/v1`) | – |

Builder Actions: ADD_NODE, DELETE_NODE, MOVE_NODE, DUPLICATE_NODE, UPDATE_PROPS, UPDATE_STYLES, UPDATE_RESPONSIVE,
UPDATE_VISIBILITY, UPDATE_LINK, REORDER_CHILDREN, WRAP_NODE, UNWRAP_NODE, LOCK_NODE, UNLOCK_NODE, HIDE_NODE, SHOW_NODE,
REPLACE_MEDIA, INSERT_BLOCK, APPLY_THEME. A batch is atomic: one failing action rejects the whole batch.

Responses use the report's envelope (`{success, data, meta.requestId}` / `{success:false, error:{code,message,details}, requestId}`).

## Design notes / deviations from the report

- **Express + `pg` instead of NestJS + Prisma.** The layering is the same (routes → service → repository → pure domain),
  and `pg` returns BIGINT as strings so ids never pass through `Number`. Moving to NestJS/Prisma later only touches the
  routes and repository files.
- **IDs** are Snowflake-generated 63-bit values (`src/common/ids.ts`), stored as BIGINT, handled as validated decimal
  strings in TypeScript (instead of `bigint`) and returned as JSON strings. Path ids above 2^63-1 are rejected.
- **Outbox** rows are written in the same transaction as the revision. A built-in poller (`FOR UPDATE SKIP LOCKED`)
  drains them to a pluggable publisher that currently just logs. Redis/BullMQ is not wired in; plug a publisher into
  `src/outbox/worker.ts` when it's needed.
- **Idempotency**: results are stored in `idempotency_keys` inside the mutation transaction; a retry with the same key
  and body replays the stored response (`Idempotent-Replayed: true`), a different body gives `IDEMPOTENCY_CONFLICT`.
- **Not enforced yet (external services):** asset ownership/tenant checks against the Media service and page ownership
  against the Page API. Asset ids are format-checked and tracked in `document_references`; add the cross-service check
  where `collectReferences` is used in `document.service.ts`.
- Revisions are immutable at the database level (trigger blocks UPDATE/DELETE). Revision numbers are INTEGER per document.
- Extra error codes beyond the report: `BAD_REQUEST`, `INVALID_IDENTIFIER`, `UNSAFE_CONTENT`, `DOCUMENT_LOCKED` (423),
  `DOCUMENT_EXISTS`.
- Not built (out of the report's P0/P1 scope): public renderer endpoints, signed preview tokens, schema migration engine,
  Prometheus metrics.
